# Lithium 思路首批适配与验证

日期：2026-10-15。分析基线为 `a81b44b`（Minecraft/Folia 26.3）。[完整迁移分析](lithium-migration-analysis.md)保留该基线的覆盖判断，本文记录随后进行的实现与实测。

## 实现范围

| 机制 | 本轮实现 | 保留的工作或限制 |
| --- | --- | --- |
| 空方块效果 | 空步骤快退、四组集合延迟创建 | 活跃效果保持 before/effect/after 顺序、来源位置和死亡中断 |

## 先处理的现有问题

- 移除 `GoToClosestVillage` 跨世界共享的静态 TTL 缓存，改为读取当前世界 POI 索引；旧缓存时长字段仅为配置兼容保留。
- 异步寻路使用任务私有的 palette、世界边界、路径类型缓存和生物参数。准备、起点计算及实体生命周期钩子留在 owner 线程；后台只扩展已审计的 Walk/Fly/Swim 节点。
- 不支持的 evaluator、非原生实体、跨区域输入、过大范围或依赖动态碰撞的场景逐请求同步回退。普通同步结果也正确更新导航目标、reachRange 和卡住计时。
- 异步失败/null 结果正常结束为不可达，单个完成回调异常不再阻断其他通知；跨维度后不执行捕获旧实体或旧世界的回调；HOME 寻路不会把不可达结果写成目标。

**异步覆盖率限制：** 当前快照复制输入 chunk 的全部高度。步行请求的输入包含水、熔岩或动态形状时会同步回退，即使它们远在地下；palette 保留已移除类型时也可能保守回退。复制发生在 owner 线程，存在 CPU 和分配成本。这里验证的是读取隔离和回退行为，不能据平地走廊宣称自然地形异步吞吐保持或提升。

另一个既有性能限制仍保留：`AsyncPath.process()` 与 `postProcessing()` 使用同一实例锁，整次求解期间持锁；worker 先取得锁时，owner 注册回调可能等待搜索结束。本轮没有改动这一并发协议，也不声称异步寻路已无阻塞。

## 性能测量口径

同一份包含前置修复的 JAR，分别关闭/开启七个新开关；其他 Lithium 开关保持开启。每轮使用独立固定 seed 平坦世界、两个相隔 2,048 格的真实 TCP 玩家、两个 Folia 区域线程。测量通过所属实体调度器执行，两个区域依次计时，避免互相竞争；最终测量为每个场景二十轮预热、二十轮记录，四个进程按 OFF、ON、ON、OFF 顺序运行。

运行环境为 x86_64、Oracle JDK `25.0.4.1+1-LTS-5`，容器 CPU 配额为 4 核，JVM 堆为 `-Xms1G -Xmx3G`。计时期间不并行运行 Gradle 或其他基准。早期诊断使用四轮预热、十轮记录，不与最终样本混合。

记录线程 CPU 时间、墙钟耗时、ThreadMXBean 分配字节和可观察工作次数。活跃场景与空闲场景一起测试；Brain 包含 96/4 行为、稳定条件与每 tick 改变记忆的对照。方块实体使用真实 LevelChunk ticker wrapper，批量场景为每类 64 个 BE；包含 wrapper 内部检查，**不包含外层 Level 调度循环**。

Brain 场景在真实村民上执行完整 `Brain.tick`、保留其传感器，但使用构造的 96／4 任务图，不是原样原版村民 AI 的整服负载。这里也没有完成所有 DAB／异步寻路配置组合的性能矩阵。

重复调用共享当时的游戏时间，因此这是实际服务器线程中的子系统基准，不是自然 20 TPS 负载，更不能直接换算整服 TPS/MSPT 百分比。正常 ticking 下的设备进度、移动、事件与存盘另由端到端断言验证。

同产物 OFF 仍包含 Brain 版本维护等共同成本。原 `a81b44b` 产物的补充测量单独列出，避免把两种基线混在一起。

## 最终测量结果

最终 ABBA 共 29 个场景、4,640 个测量样本；原产物参考另有 1,160 个样本。每个场景、进程、区域保留完整 20 轮，没有筛掉离群值。两种配置及原产物的可观察工作次数全部相同。下表是合并样本的中位数，不是置信区间，也不把同一进程内的轮次当作独立进程重复。每进程及每区域的分布另见汇总 JSON。

### 局部工作和 AI

CPU 单位为 ns/次，分配为 B/次；变化为 ON 相对同产物 OFF，负值表示耗时降低。高度图的一次操作是一对置石／置空气（两次 `Level.setBlock`）；Brain 是完整一次 tick，频繁变化组还包含记忆写入；搜索是完整一次 `findNearestBlock`。各场景的完整单位定义见汇总 JSON。

| 场景 | OFF CPU | ON CPU | 变化 | 分配 OFF → ON |
| --- | ---: | ---: | ---: | ---: |
| 每次新建空效果收集器 | 376.6 | 7.4 | -98.0% | 1,120.0 → 40.0 |
| 复用空效果收集器 | 286.5 | 5.0 | -98.3% | 496.0 → 0.0 |
| 每次新建活跃效果收集器 | 352.2 | 125.5 | -64.4% | 1,144.0 → 504.0 |
| 复用活跃效果收集器 | 237.7 | 85.4 | -64.1% | 352.0 → 64.0 |
| 高度图长距离下降 | 6,693.3 | 3,345.6 | -50.0% | 611.2 → 238.5 |
| 高度图近表面更新 | 871.8 | 771.8 | -11.5% | 307.7 → 126.8 |
| 游戏事件，无接收者 | 538.9 | 351.8 | -34.7% | 1,112.1 → 264.0 |
| 游戏事件，有接收者 | 589.1 | 408.7 | -30.6% | 1,292.0 → 452.0 |
| 96 任务 Brain，稳定未满足条件 | 6,453.5 | 3,106.2 | -51.9% | 6,268.1 → 3,603.7 |

空收集器、高度图长下降、游戏事件与稳定的多任务 Brain 都有较一致的方向；例如四对进程／区域中，长下降 CPU 变化为 −54.2% 至 −45.0%。近表面更新的绝对收益较小，不宜据长下降场景概括所有方块修改。

频繁改变记忆时不能确认 Brain 有稳定 CPU 收益：96 任务四对变化为 −7.1% 至 +7.0%，4 任务为 −8.2% 至 +18.1%。小型 Brain 的池化 −0.3% 应视为没有已证实改善。版本失效、状态扫描和传感器仍然存在；减少分配也不等于所有场景 CPU 都下降。

海龟蛋剪枝以额外缓存分配换取较长搜索的减少：本场景每次多 472 B。首平面很快命中时，前八次直接检查避免了缓存分配，但仍有约 **7.8 ns/次、7.8%** 的测量代价；四对均增加（+4.7% 至 +14.1%）。因此它适合稀少目标和空搜索，不能表述为近目标无成本。

### 方块实体休眠

这里采用 64 个真实 wrapper 的批量结果，已除以 64，单位为 **ns/BE** 和 **B/BE**。单个 wrapper 的另外四个空闲场景也全部保留在原始数据中。活跃组表示不可休眠状态：合成器维持倒计时、营火烹饪但不完成、潜影盒保持打开、漏斗解锁并执行空查询；不是满产能设备吞吐测试。其 `work=64` 记录 ticker 调用次数，实际产出／进度另由正常 tick 功能断言验证。

| 设备及状态 | OFF CPU | ON CPU | 变化 | 分配 OFF → ON |
| --- | ---: | ---: | ---: | ---: |
| 合成器，空闲／可休眠 | 26.48 | 23.80 | -10.1% | 0.00 → 0.00 |
| 合成器，不可休眠 | 26.98 | 32.10 | +19.0% | 0.00 → 0.00 |
| 营火，空闲／可休眠 | 41.55 | 23.70 | -43.0% | 0.00 → 0.00 |
| 营火，不可休眠 | 213.55 | 219.43 | +2.8% | 120.00 → 120.00 |
| 潜影盒，空闲／可休眠 | 33.67 | 28.51 | -15.3% | 0.00 → 0.00 |
| 潜影盒，不可休眠 | 46.60 | 48.62 | +4.3% | 18.48 → 17.48 |
| 漏斗，空闲／可休眠 | 41.43 | 25.83 | -37.7% | 0.00 → 0.00 |
| 漏斗，不可休眠 | 139.96 | 145.10 | +3.7% | 156.00 → 176.00 |

四类设备的空闲场景在四对区域比较中均改善。但不可休眠合成器的 CPU 明确增加，四对为 +8.1% 至 +22.4%，池化为 **+19.0%，约 5.1 ns/BE**。其他活跃设备也有正的池化差值，进程间波动较大；活跃漏斗的分配中位数还增加了 20 B/BE。不能只报告睡眠收益而忽略这些状态下的成本，也不能据此推断所有装置的净收益。

这支持把保守休眠用于空闲占比较高的负载；持续满负载设备应单独测量，必要时关闭 `block-entity-sleeping`。本轮没有测驻留索引／缓存内存的长期变化，分配量仅指测量期间的线程分配。

### 原产物参考与共同成本

原 `a81b44b` 是额外的一次新进程、两个区域的参考运行，不能与两次 OFF／两次 ON 当作对等重复，也不能把全部差值归因于某一项改动。它的用途是检查同产物 OFF/ON 共同包含的新成本。

| 场景 | 原产物 CPU | 最终 OFF CPU | 最终 ON CPU | ON 相对原产物 |
| --- | ---: | ---: | ---: | ---: |
| 96 任务稳定条件（ns/次） | 6,072.95 | 6,453.51 | 3,106.17 | -48.9% |
| 4 任务记忆频繁变化（ns/次） | 646.96 | 654.90 | 653.08 | +0.9% |
| 高度图长下降（ns/次） | 6,607.66 | 6,693.34 | 3,345.63 | -49.4% |
| 海龟蛋首平面命中（ns/次） | 94.96 | 99.86 | 107.66 | +13.4% |
| 空闲合成器（ns/BE） | 26.58 | 26.48 | 23.80 | -10.5% |
| 活跃合成器（ns/BE） | 27.24 | 26.98 | 32.10 | +17.8% |
| 锁定漏斗（ns/BE） | 34.92 | 41.43 | 25.83 | -26.0% |
| 活跃漏斗（ns/BE） | 124.10 | 139.96 | 145.10 | +16.9% |

原产物参考支持大型稳定 Brain、长高度图扫描和空闲 BE 的收益方向，同时保留了近目标搜索与活跃 BE 的代价。Brain 的版本维护在新开关关闭时也存在，不能用同产物 OFF/ON 推断其零成本；原产物比较仍受单次进程与 JIT 差异影响。小型 Brain 频繁变化相对原产物 +0.9%，也不足以声称确定退化或改善。
